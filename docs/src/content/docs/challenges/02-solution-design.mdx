## Objective

Produce the AVD **High-Level Design** from the assessment: **topology** (host pools per persona),
**identity** (Entra-joined + Intune by default), **FSLogix** profile storage, **networking**,
**golden image**, **autoscaling**, and **BCDR** — every choice mapped to an **Azure Verified
Module** so it is directly buildable in `infra/`.

## The agentic way (do this first)

- **Agent:** `avd-architect`.
- **Skills:** `avd-landing-zone` (AVM module map), `avd-fslogix` (profile storage), `avd-personas-sizing`,
  `avd-evidence-pack` (the `hld.md` template).
- **MCP:** `microsoft-learn` for AVD reference architecture; `azure` / `terraform` to confirm
  module availability.

## Evidence artifact

`hld.md` — topology, identity, FSLogix, network, image, scaling, BCDR, plus an AVM module map and
an architecture diagram.

## Definition of done

- **Host pools** mapped to personas (pooled multi-session vs. personal) with sizing from C01.
- **Identity** decision stated (Entra-joined + Intune; hybrid only where on-prem apps require it).
- **FSLogix** on **Azure Files Premium (Kerberos)** with share sizing; ANF only > 1,000 users.
- **Network**, **golden image** pipeline, **scaling plan**, and **BCDR** all designed.
- An **AVM module map** and a **diagram** make the design buildable in `infra/`.

<Aside type="note" title="Defaults that matter">
  Region default `swedencentral`; identity Entra-joined + Intune; profile storage FSLogix on Azure
  Files Premium. Deviate only with a documented reason.
</Aside>
