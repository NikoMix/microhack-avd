## Objective

Review the HLD against the **Azure Well-Architected Framework** through an **AVD lens** —
**Cost, Performance Efficiency, and Reliability** first — and produce a **prioritised findings
list** with a **decision register**, instead of generic advice.

## The agentic way (do this first)

- **Agent:** `avd-waf-reviewer`.
- **Skills:** `avd-waf-lens` (the AVD-specific WAF checklist), `avd-cost-guardrails`.
- **MCP:** `microsoft-learn` for WAF guidance; `azure` (Advisor) for live recommendations.

## Evidence artifact

`waf-review.md` — Cost / Performance / Reliability findings (and the other pillars), each with a
severity and a recommendation, plus a decision register.

## Definition of done

- Findings span the pillars, **prioritising Cost, Performance, and Reliability** for AVD.
- Each finding has a **severity** and a **specific, actionable** recommendation.
- A **decision register** records each finding as accepted / mitigated / deferred, with rationale.
- Findings are **specific to this HLD** — not generic WAF boilerplate.

<Aside type="tip" title="Make it specific">
  "Right-size the session-host SKU to D-series and cap pooled sessions at 8" beats "consider cost
  optimisation". Tie every finding to a line in the HLD.
</Aside>
